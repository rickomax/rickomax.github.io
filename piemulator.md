PIEMulator runs the DOS programs of Pie in the Sky Software's **3D Game
Creation System** (GCS, 1993-95) on today's computers: the games made with
it, its POWER 3D engine, and GCS itself, with its level editor, paint
program and build tools. No DOS box is needed. You can play the games just
as they looked in 1995, or turn on an OpenGL view with widescreen, mouse
look and modern controls.

## No original code inside

PIEMulator is not built from the source code of GCS, its engine or any game.
Pie in the Sky's source code was never used. Everything PIEMulator knows
about those programs was learnt from the programs themselves, as they were
shipped.

The download does not contain the original programs either, nor any
recompiled code made from them. It holds only PIEMulator's own code: a
reimplementation of the PC the games were written for, and the tools that
recompile a game.

**Games are recompiled on your own computer, each time you play.** When a
game starts, PIEMulator reads the game's own programs from your folder and
turns them into native code in memory. When you close the game, that code is
gone. Nothing made from a game is ever sent anywhere or shipped with
PIEMulator.

## How it works

The games are 16-bit DOS programs. They expect a PC from the early 1990s:
its processor, DOS, a VGA card, a Sound Blaster, an AdLib music card,
expanded memory and a mouse. PIEMulator rebuilds that PC in software, and
runs the game's own programs on it.

1. **Your files.** The game's folder holds its programs and data exactly as
   they were shipped. PIEMulator reads them from there and changes nothing in
   them.
2. **Recompiling.** When DOS loads one of the game's programs, PIEMulator
   follows its machine code from the start, translates what it finds into C,
   and compiles that C in memory with a small built-in compiler (TinyCC).
   The result runs at full speed on your processor. This takes a fraction of
   a second.
3. **The interpreter.** Some code can't be found ahead of time: code reached
   through tables, code a program writes or changes as it runs, code loaded
   from data files (such as the guards' scripts). That code runs on an
   interpreter, a processor in software, as an emulator would.
4. **Learning.** While you play, PIEMulator notes where the interpreter had
   to step in, and about once a second recompiles the game with what it has
   seen, in the background. After a few seconds of play almost everything
   runs as native code. What it learnt is kept for next time, as a list of
   addresses only: no code from the game.
5. **Only known games are compiled.** Before compiling a program,
   PIEMulator checks it against the list of the games' programs it knows
   (by their SHA-256). A program that is not on the list, or has been
   changed, still runs, but only on the interpreter, which can never reach
   outside the emulated PC.

### The OpenGL view

The engine still draws each frame with its own renderer, because the game
depends on it: a guard the engine doesn't draw never shoots. PIEMulator
watches the engine as it draws, and takes from it what it has already
decided: which walls, sprites and enemies are visible, where they are, which
picture each one shows, and how it is lit. It then draws that same scene as
real 3D with OpenGL, at your window's resolution.

- **Mouse look.** The engine has no looking up and down. The OpenGL view
  turns its camera up to about 70&deg;, so the floor and ceiling come into
  view as they would in a true 3D game. Shots still fly level.
- **The original look.** The textures keep their 256 colours and the
  engine's own lighting rules, worked out for each pixel: fading with
  distance, flashes when you are hit or pick something up, flickering
  lights.
- **What's on top stays on top.** Menus, the HUD, messages, the map and the
  pause screen are the engine's own drawing, unchanged.
- **Widescreen.** The view widens to fill the window while the vertical
  field of view stays the same. The engine passes on everything within its
  drawing distance, so the extra width shows real geometry.
- **Smooth play.** The game runs on a thread of its own. Drawing the window
  and waiting for the display never hold it up, and the emulated VGA
  refreshes in step with your display.

## Getting started

1. **Download** the build for your system and extract it to a folder of its
   own, for example `C:\Games\PIEMulator` or `~/piemulator`.
2. **Add your games.** Put each game in a folder inside `games`, next to
   `gcs`. Each game in the list has a usual folder name, shown on the right
   when you select it. Or keep the game where it is and choose its folder
   with **...**.
3. **Start it.** Run `gcs.exe` on Windows, or `gcs` on Linux. It opens the
   game list.
4. **Pick a game and press Play.** The game starts in the same window, and
   the list comes back when it ends.

The game's folder needs the game as it was shipped, its programs included.
PIEMulator finds the game anywhere up to three folders deep inside it, so an
unpacked archive can be used as it is. To use GCS itself, put its folder,
named `GCS`, next to `gcs`.

## Controls

While the 3D view is being played, PIEMulator adds modern controls. Each
key or button below sends one of the game's own keys, so the game handles
it as it always did.

<div class="ar-options" markdown="1">

| Press | Does | Game's own key |
|---|---|---|
| <kbd>W</kbd> / <kbd>S</kbd> | Walk forward / backward | Keypad up / down |
| <kbd>A</kbd> / <kbd>D</kbd> | Sidestep left / right | Keypad 1 / 3 |
| Mouse | Turn, and look up and down in the OpenGL view | |
| Left mouse button | Fire | <kbd>Ctrl</kbd> |
| Right mouse button, <kbd>E</kbd> | Pick up, read a memo | <kbd>I</kbd> |
| <kbd>Space</kbd> | Jump | Keypad 0 |
| <kbd>Q</kbd> | Choose an object to drop | <kbd>S</kbd> |

</div>

All the game's other keys still work: weapons <kbd>1</kbd> to <kbd>9</kbd>,
the map, <kbd>Esc</kbd> and the rest. In menus, on the map and on the
pause and help screens, <kbd>W</kbd> <kbd>A</kbd> <kbd>S</kbd> <kbd>D</kbd>
move like the arrows and <kbd>E</kbd> chooses; everything else behaves as in
the original. Some games come with bindings of their own, to match their
controls.

**Controls** (<kbd>F2</kbd> in the game list) changes the bindings, for the
selected game or for every game. There are three sets: *Playing*,
*Inventory* (while you choose an object to drop) and *Menus*. Click an input
and press the game's key it should send, or choose *Pick up*, *None*, or
*Clear* to go back to the default. *Add input* takes any key, mouse button
or the mouse wheel.

## The settings file

The game list keeps its settings in `gcs.cfg`, next to `gcs` (or in your
user settings folder, if that one can't be written). It can also be edited
by hand:

```
start_maximized=1        # every game's window opens maximized
start_fullscreen=1       # every game opens in fullscreen
mouse_sensitivity=1.5    # 0.25 to 2.5
volume=80                # 0 to 100
show_adult=1             # list games with adult content
bind.all.e=i             # E picks up in every game
bind.all.wheelup=2       # the mouse wheel picks weapons 2 and 3
bind.all.wheeldown=3
bind.all.menu.q=esc      # in the menus, Q backs out
```

What PIEMulator knows of each game (its name, folder, default bindings) is
in `games.ini`, next to `gcs`. A `games.ini` in your user settings folder is
read after it, to add games or change them, without touching the installed
one.

## Troubleshooting

<div class="ar-faq" markdown="1">

<details markdown="1">
<summary>The game list can't find a game</summary>

Select the game and choose its folder with **...**. The folder must hold
the game as it was shipped, programs included; an installer or a
compressed archive must be installed or unpacked first.
</details>

<details markdown="1">
<summary>A game runs slowly, and the console says it "is not a known game executable"</summary>

That game's program is not one PIEMulator knows, often because it was
changed or comes from a release not on the list. It still runs, but only on
the interpreter. Please tell us which game and release it is, so it can be
added.
</details>

<details markdown="1">
<summary>Windows warns that the program is from an unknown publisher</summary>

The beta builds are not signed yet; the warning does not mean anything
harmful was found. Choose **More info**, then **Run anyway**. Or, before
unpacking, right-click the downloaded `.zip`, choose **Properties**, tick
**Unblock** and press **OK**.
</details>

<details markdown="1">
<summary>GCS says "This program cannot be run in DOS mode"</summary>

On Windows, don't copy `gcs.exe` into the GCS folder: Windows ignores case
in file names, so it replaces GCS's own `GCS.EXE`. Put the original
`GCS.EXE` back, and keep `gcs.exe` outside the folder.
</details>

<details markdown="1">
<summary>The mouse doesn't turn the view</summary>

The modern controls only take over while the 3D view is being played. If
the mouse is still free, press <kbd>Alt</kbd>+<kbd>F11</kbd> to capture it,
and check that the modern controls are on (<kbd>Alt</kbd>+<kbd>F7</kbd>).
</details>

<details markdown="1">
<summary>The controls don't match the game's instructions</summary>

The modern controls change them on purpose. <kbd>Alt</kbd>+<kbd>F7</kbd>
turns them off, for the game's original keys. To change a single key, use
**Controls** in the game list.
</details>

<details markdown="1">
<summary>I can't type a name, or a letter does something else</summary>

Hold <kbd>Alt</kbd> while typing: <kbd>Alt</kbd> with a key sends that key
itself, whatever it is bound to.
</details>

<details markdown="1">
<summary>Something looks wrong in the OpenGL view</summary>

Press <kbd>Alt</kbd>+<kbd>F9</kbd> to switch to the engine's own renderer,
and let us know which game and where.
</details>

<details markdown="1">
<summary>On Linux, the folder picker doesn't open</summary>

It needs `zenity` or an xdg-desktop-portal. You can also type the folder:
select the game and press <kbd>Tab</kbd>.
</details>

</div>

## Limitations

- No network, modem or serial play.
- No joystick: it reads as absent, as on a PC without one.
- PIEMulator is a beta. Not every game has been played through to the end.
